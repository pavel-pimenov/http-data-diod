### Из релевантного апстрима (v0.62.0 + v0.63.0)

* **Сервер — монтирование статики**: `set_mount_point()` теперь обслуживает путь
  только без `.`, `..` и пустых сегментов кроме финального `/`. Прочие варианты
  отдаются с 404 (ранее разрешались через ФС). Обслуживаются только обычные
  файлы, если реальный путь не резолвится — `set_mount_point()` возвращает `false`.
  Редирект директории с относительным `Location` использует `./<last-segment>`
  с корректным процентным кодированием.
* **Сервер — фрейминг/заголовки**: запрос без `Host` в HTTP/1.1, строка запроса
  не по одному пробелу, `#` в request-target — 400. `Content-Length`/`Transfer-Encoding`
  от хендлера заменяются вычисленными; 1xx/204/304 не несут `Content-Length`.
  Ответ без длины/`chunked` при отключённом keep-alive закрывает соединение.
  Запрос с и `Transfer-Encoding`, и `Content-Length` или `Transfer-Encoding`
  в HTTP/1.0 — закрывает соединение. Тело запроса можно прочесть только один раз,
  при частичном чтении соединение закрывается.
* **Клиент/редиректы/прокси**: при 303 тело не переотправляется; `Location`
  не декодируется перед фоллоу-апом, относительные резолвятся по RFC 3986 §5.2.
  URL с userinfo или бэкслешем в авторитете даёт невалидный клиент. `CONNECT`
  не 200 — `Error::ProxyConnection` (407 по-прежнему как ответ). Креды прокси
  и лимиты/TLS-настройки переносятся при кросс-хост редиректе. `Expect: 100-continue`
  с ранним ответом не оставляет соединение открытым. Digest `uri` подписывается
  по отправленному request-target.
* **WebSocket**: сервер проверяет подпротокол по списку клиента, клиент валит
  хендшейк при не предложенном подпротоколе. Закрытие соединения после
  WebSocket-upgrade с телом. Пинги без спуриус-вейкапов. Валидация Close-фрейма.
* **SSE**: игнорирование BOM, CR как line ending, пустой `id` сбрасывает
  `Last-Event-ID`, невалидный `id` игнорируется.
* **TLS**: усилена проверка клиентских сертификатов на серверах с `client_ca`,
  проверка сертификата сервера при хендшейке на OpenSSL, корректировка verify
  на разных бэкендах, лимиты `PemMemory` по длине.
* **Ограничения**: таймаут на весь request head, лимиты на SSE/WebSocket payload,
  `0` трактуется как «без лимита» для ряда настроек, защита от рекурсии/квадратичности.

### Влияние на проект
Переопределения из `src/cpp_httplib_config.h` (`CPPHTTPLIB_SEND_BUFSIZ`/`RECV_BUFSIZ`
1 MB, `CPPHTTPLIB_KEEPALIVE_MAX_COUNT` 200, `CPPHTTPLIB_THREAD_POOL_COUNT` 64,
таймауты 300s, `CPPHTTPLIB_TCP_NODELAY`) в новой версии используются как раньше.
Использование API проекта (`set_content`/`set_content_provider`, статические маршруты,
клиентские вызовы) не требует правок. В коде нет `set_mount_point`/особых
работ с клиентскими сертификатами/прокси-настроек httplib, поэтому поведение сервиса
не должно измениться. Релизные фиксы закрывают ряд edge-case'ов фрейминга/TLS.
