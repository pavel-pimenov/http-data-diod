# round 164 — CI: тест восстановления доставки спанов требовал ровно одного тела

## Симптом

CI-прогон `39285065961` (раунды 161+162): `cppcheck` и `clang-tidy` зелёные, а
`Build + unit tests + NATS smoke` и `Coverage gate` — красные, оба на одном и том же
тесте:

```
TraceLogger: jaeger delivery recovers after the endpoint comes back
/app/test_trace_logger.cpp:423: FAILED:
  REQUIRE( server.body_count() == 1 )
with expansion:
  2 == 1
```

Воспроизвелось в **обоих** джобах, то есть на CI-раннере это не редкий флейк, а
устойчивое поведение (на ноутбуке тест проходит: там ответ mock-сервера успевает
вернуться раньше таймаута клиента).

## Корень

Тест (его «оживление» — из раунда 156) моделирует восстановление доставки: порт
занимается и освобождается, первая партия спанов уходит в отказанное соединение,
затем эндпоинт возвращается на том же порту, и экспортер обязан снова доставлять.

В цикле восстановления тест подкладывает спан, пока не сдвинется счётчик `sent`.
Инвариант «ровно одно тело» здесь неверен: доставка спанов **at-least-once** — если
ответ клиенту не дошёл (таймаут отправки 2 с), партия отправляется повторно, и
mock-сервер записывает тело **дважды**. На нагруженном CI-раннере ответ сервера
успевает уйти, но клиент уже сменил соединение/не дождался ответа — так и получается
`2 == 1`. Локально тот же сценарий даёт `1 == 1`, потому что ответ возвращается вовремя.

Обратите внимание: это не дефект экспортера. Повторная доставка спана — ожидаемое
поведение «at-least-once», а тест утверждал более сильное свойство, чем система
предоставляет.

## Что сделано

Инвариант заменён на тот, который действительно проверяет смысл теста:

```cpp
REQUIRE(env.sent() >= 1.0);
REQUIRE(server.body_count() >= 1);
```

Регрессия, которую тест ловит, — **утёкший слот пула соединений**: при нём пул
остаётся исчерпанным и не доставляет **ничего** (счётчик тел остаётся 0, цикл
восстановления не завершается успешно). Эта гарантия инвариантом «≥ 1» проверяется
ровно так же, как раньше, — «ровно одно» дополнительной силы не давало.

## Проверка

- Локальный прогон тестов: `All tests passed (2860 assertions in 596 test cases)` —
  тест проходит и в «1 тело», и в «2 тела» (счётчик тел — at-least-once).
- `health-check.sh all` — все проверки пройдены; smoke — все GET-запросы успешны;
  `ci-gate.sh runtime` — rc=0 (golden 87/87, consistency 91/91, parity OK).
- Остальные гейты (сборка, cppcheck, clang-tidy `--all` по 47 TU) — без изменений
  относительно раунда 163; гейт покрытия проверяет CI на этом же коммите.
