# Round 84: достижимые ветви DB-слоя (hex-ниббл bytea + идемпотентный re-init)

## Мотивация

После round 81–82 в DB-слое остались единичные непокрытые строки. Прогон по
`db_query_executor_postgres.cpp` и `db_query_handler.cpp` показал, что большинство
остатка — защитные/недостижимые пути (`PQconnectdbParams == nullptr`,
`num_fields == 0`, многострочные `Logger::*` — артефакт атрибуции gcovr) и пул
ошибок libpq, который детерминированно не воспроизвести. Но две цели оказались
реально достижимыми:

* `db_query_executor_postgres.cpp` — хелпер `nibble` в `hex_to_bytes`: ветви для
  строчных `a..f` (103–104) и заглавных `A..F` (106–107). Существующий фикстур
  `'\x0102'::bytea` содержит только цифры, поэтому буквенные ветви не набирались.
  Заглавные недостижимы: штатный вывод `bytea` из PostgreSQL всегда в нижнем
  регистре (`\x01ab`), так что реально закрываются 103–104.
* `db_query_handler.cpp` — строка 21 (`continue`, когда исполнитель для данного
  имени уже создан): повторный `init()` с тем же именем БД. Идемпотентность не
  покрывалась ни одним тестом.

## Изменения

* `test_db_live.cpp`: фикстурный `bytea` изменён `'\x0102'` → `'\x01ab'` (байты
  `00...` нет — `0x01 0xab`), утверждение base64 `AQI=` → `Aas=`; так `nibble`
  получает и цифры, и строчные буквы (покрывает 103–104).
* `test_db_live.cpp`: новый `TEST_CASE("DbQueryHandler: re-init keeps already
  ready executors", "[db-live]")` — двойной `init()` с одним и тем же именем БД,
  проверка что повторный проход пропускает существующий исполнитель (строка 21)
  и запросы продолжают обслуживаться.
* `docs/coverage-baseline.json` пересобран скриптом `--update`.
