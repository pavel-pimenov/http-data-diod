# Round 220 — Промт: хеш запроса как ссылка на сам запрос; в PDF — таблица

## Задача
Поправить системный промт AI-генерации отчёта так, чтобы хеш запроса (SQL_ID) в
рекомендациях был ссылкой на сам запрос; если клик невозможен (PDF) — оформить
сам запрос и рекомендацию в виде таблицы.

## Реализация
### `scripts/spider_report.py` — системный промт `_AI_SYSTEM_PROMPT`
Переработаны пункты 3–8:
- **п.3** — в рекомендациях указывать конкретные SQL_ID, модули, схемы, таблицы из данных;
- **п.4** — хеш запроса (SQL_ID) оформлять как Markdown-ссылку на сам запрос
  `[SQL <SQL_ID>](#sql-<SQL_ID>)` → раздел «## Полные тексты запросов» в конце отчёта
  с полным текстом запроса в блоке кода (если текст есть в данных; иначе — пометка
  «текст недоступен в дампе»);
- **п.5** — если клик по ссылке невозможен (PDF): оформлять рекомендацию таблицей
  `| SQL_ID | Сам запрос (обрезан до 200 символов) | Рекомендация |`;
- **п.6–8** — приоритизация, без выдумок, язык русский.

## Поведение PDF-конвертера
`spider_report_pdf.py::_escape_md` (строка 139) убирает URL из Markdown-ссылок
`[текст](url)` → в PDF клик недоступен, поэтому модель идёт по пути таблицы (п.5),
что подтверждено на практике.

## Проверка (пересборка контейнера + генерация)
- `docker compose build l2-spider-ai` + `docker compose up -d --force-recreate l2-spider-ai` — образ собран, контейнер поднят;
- новый промт в контейнере (`grep "Хеш запроса (SQL_ID)" /usr/local/bin/spider_report.py` → 1, `grep "Полные тексты запросов"` → 1);
- `POST http://localhost:19096/generate` → running → done (без ошибок);
- в новом `spider-output/ai/report.md`:
  - рекомендации с реальными SQL_ID;
  - таблица `| SQL_ID | Сам запрос (обрезан до 200 символов) | Рекомендация |` (строка 239) с обрезанным текстом запроса (напр. `DECLARE job BINARY_INTEGER := :job; ...` для `bj9pq2wpng4s5`);
  - новый `report.pdf` сгенерирован (296 КБ), HTTP 200.
