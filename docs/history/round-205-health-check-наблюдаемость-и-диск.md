# round 205 — health-check видит наблюдаемость и диск (инцидент с VictoriaMetrics)

## Что было не так

27 октября 2026 в 12:04 UTC `l2-victoria-metrics` умер с
`mkdir .../merged: no space left on device` — диск был занят под 97 %.
Контейнер остался лежать **~43 часа**, и этого никто не заметил:

- `health-check.sh` проверял только `l2-proxy`, `l2-worker`, `l2-server`,
  `nginx` и `jaeger`; `victoria-metrics`, `vmagent`, `vmalert`, `nats-server`,
  `nats-exporter` и `perses` не проверялись вообще;
- `docker ps` при этом показывал `Up 44 hours (healthy)`, а `docker inspect`
  и Docker API для того же контейнера — `exited (2)`: состояние демона
  разъехалось после падения по диску, и «зелёный» статус был ложным;
- `vmagent` всё это время писал в лог `lookup victoria-metrics ... server
  misbehaving` и копил блоки в буфере, но ни один алерт не срабатывал —
  алерты живут в `vmalert`, который спрашивает тот же мёртвый VictoriaMetrics
  (замкнутый круг: хранилище метрик не может алертить о своём падении).

То есть прикладной трафик шёл нормально, а наблюдаемость молча стояла.

## Что сделано

### `health-check.sh`: наблюдаемость и диск

- Новый набор проверок `check_metrics_stack()`:
  - `victoria-metrics` (`:8430/health`) — **критично**, хранилище метрик;
  - `vmagent` (`:8429/health`) — **критично**, сборщик;
  - `vmalert` (`:8880/health`) — **критично**, правила оповещения;
  - `nats-server` (`:8222/healthz`) — **критично**, транспорт;
  - `nats-exporter` (`:7778/metrics`) и `perses` (`:8089/api/v1/projects`) —
    проверяются, но помечаются некритичными (доп. метрики NATS и UI).
- Для критичных сервисов выполняется попытка рестарта и повторная проверка.
  `restart_service()` получил второй параметр — имя контейнера, потому что
  у части сервисов оно не совпадает с именем сервиса compose
  (`victoria-metrics` → `l2-victoria-metrics`, `perses` → `l2-perses`).
- **Найденный по ходу баг**: и `docker compose ps`, и `docker ps` без `-a`
  не показывают **остановленный** контейнер, то есть ровно тот случай, ради
  которого рестарт и нужен. Оба вызова переведены на `-a`.
- Новая проверка диска `check_disk_space()`: предупреждение ниже
  `DISK_WARN_MB` (2048 МБ), ошибка ниже `DISK_CRIT_MB` (1024 МБ). Порог
  критичности выбран выше 0.9 ГБ — значения, при котором упал VictoriaMetrics.
  Путь и пороги переопределяются (`DISK_CHECK_PATH`, `DISK_WARN_MB`,
  `DISK_CRIT_MB`).
- Новые режимы: `./health-check.sh metrics` (только наблюдаемость) и
  `./health-check.sh disk`. Для одиночных режимов теперь печатается итог.
- `rebuild-and-run.sh`: порог авто-очистки build cache поднят с 1024 до
  2048 МБ — тот же инцидент показал, что 1 ГБ свободного места уже мало.

## Проверка

- `./health-check.sh metrics` и `./health-check.sh disk` — rc=0 на живом
  стеке; `./health-check.sh all` — rc=0, в выводе 14 проверок, включая
  `victoria-metrics`, `vmagent`, `vmalert`, `nats-server`, `nats-exporter`,
  `perses` и диск.
- **Живая проверка инцидента**: `docker stop l2-victoria-metrics` →
  `./health-check.sh metrics` обнаружил недоступность, перезапустил
  контейнер, дождался `/health` и вернул rc=0; после этого `/health` = 200.
  (Первый прогон показал «Could not find victoria-metrics in Docker» —
  отсюда и правка `docker ps -a`.)
- `shellcheck` rc=0 (только прежние info-замечания), `./scripts/ci-gate.sh
  offline` — зелёный.

## Ограничения (честно)

- Проверка не спасает от «замкнутого круга» алертов: если VictoriaMetrics
  лежит, `vmalert` не может об этом сообщить. Роль внешнего сторожа теперь
  играет `health-check.sh` — его нужно запускать по cron/таймеру, сам по себе
  он не работает.
- `docker ps` может врать о состоянии контейнера (разъехавшийся демон Docker
  после падения по диску); лечение — перезапуск `dockerd` в окне
  обслуживания, в этот раунд не входит.
- Диск всё ещё заполняется (сборка/логи), порог — это сигнал, а не решение.
