# Round 227 — Тесты в CI: необязательный manual-гейт, сборка без ожидания тестов

## Задача
Зелёный юнит-тест (`run_unit_tests`) в CI — длинный, и его реально гоняют на
отдельном компьютере. Сборка образа в CI не должна ждать его. Раньше оба job'а
(`run_unit_tests` и `build_docker`) были manual, и deploy-сборка всё равно была
привязана к пайплайну с тестами.

## Реализация
### `.gitlab-ci.yml`
- `run_unit_tests` (stage `test`) — остаётся **manual** на master и на тег:
  не блокирует пайплайн, запускается вручную по желанию (можно пропустить).
- `build_docker` (stage `deploy`) — на **master теперь автоматический**
  (`when: on_success` по умолчанию): сборка образа идёт сразу, **не дожидаясь**
  manual-теста. На тег остаётся manual (релиз вручную).

Итог: на master пайплайн = только deploy (сборка runtime), тест можно запустить
отдельно вручную или не запускать вовсе.

## Проверка
- YAML валиден: `stages: [test, deploy]`; `run_unit_tests.rules` — manual на обе
  ветки; `build_docker.rules` — manual на тег, автоматический на master.
- Сборка runtime (`--target runtime`) не гоняет юнит-тесты (вынесены в стадию `test`,
  раунд 226).

## Ключевое решение
Тест-гейт переведён в manual (не блокирующий), deploy на master — автоматический,
не ждёт тестов. Тесты гоняются на отдельной машине / по требованию.
