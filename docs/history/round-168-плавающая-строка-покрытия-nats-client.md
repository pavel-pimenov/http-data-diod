# round 168 — плавающая строка покрытия `nats_client.cpp`: гейт покрытия был красным из-за гонки в live-тесте

## Симптом

CI-прогон на коммите с документацией (код не менялся) дал красный `Coverage gate`:

```
production-файлы: 81, строк 6647/7261 = 91.54%
REGRESSION nats_client.cpp: 92.14% -> 91.92% (-0.22 п.п.)
FAIL: 1 регрессий, 0 новых файлов вне baseline
```

При этом предыдущий прогон на **том же коде** был зелёным (6648/7261 = 91.56%),
и разница была ровно в одной строке. Сравнение двух отчётов покрытия (артефакты
двух CI-прогонов) дало точный ответ:

```
lines differing in coverage between the green and red runs:
  line 805: green_count=3 red_count=0
```

## Корень

`src/nats_client.cpp:805` — ветка «NATS connection lost» внутри
`mark_disconnected()`: её выполняет только колбэк отключения **установленного**
соединения (`on_disconnected` → `mark_disconnected("lost connection to NATS server")`).

Live-тест «health check fails fast once the broker stops» останавливал NATS-сервер
и ждал `!client.is_connected()`. Но `is_connected()` возвращает `false` уже по
*статусу* соединения в NATS-клиенте (`natsConnection_Status(...) != CONNECTED`) —
то есть **до** того, как сработает колбэк отключения. Тест на этом заканчивался,
деструктор клиента выставлял флаг shutdown, а `on_disconnected` при shutdown
намеренно ничего не трогает («the object may be freed right after the Closed
callback is delivered») → ветка не покрывалась.

Итог: покрытие этой строки зависело от того, успел ли колбэк сработать до конца
теста. Гейт покрытия с допуском 0.0 п.п. из-за этого краснел **случайно** — то
есть в пайплайне был заложен ремонтный флейк, не связанный с изменением кода.

## Что сделано

Тест теперь ждёт именно колбэка отключения — по причине в последней ошибке
(после успешного `connect()` ошибка очищается, поэтому значение однозначно
указывает на `on_disconnected`):

```cpp
server.stop();
REQUIRE(wait_for_condition(
    [&client]() {
      const auto error = client.get_last_error();
      return error.has_value() && *error == "lost connection to NATS server";
    },
    10000));
REQUIRE_FALSE(client.is_connected());
```

Теперь покрытие строки детерминировано, а проверка стала строже: она
подтверждает не просто «клиент считается отключённым», а *конкретную причину*
потери соединения. Если колбэк не сработает, тест упадёт явно — и гейт покрытия
больше не может покраснеть «молча».

## Общий принцип

Гейт покрытия не должен зависеть от тайминга. Любая строка, покрываемая только
live-тестом с гонкой, обязана иметь в тесте явное ожидание того самого события,
которое её покрывает, — иначе пер-файловый допуск 0.0 п.п. превращается в
источник случайных красных прогонов.
