# Round 114: чистка недостижимых error-ветвей в `sentry_client`, `duplicate_detector`, `http_client`

Продолжение темы round 113: добиваем «остаток error-ветвей» — защитные проверки,
которые выглядят как обработка ошибок, но недостижимы, потому что инвариант уже
гарантирован выше по коду. Раунд не добавляет тестов: он убирает мёртвые ветви,
из-за которых в отчёте висели неукрываемые строки.

## 1. `sentry_client::parse_dsn` — две мёртвые проверки

### `project_id.empty()`

Перед разбором project id стоит:

```cpp
const size_t last_slash = rest.rfind('/');
if (last_slash == std::string_view::npos || last_slash == rest.size() - 1) {
  return std::nullopt;
}
```

Условие `last_slash == rest.size() - 1` (DSN с завершающим `/`) уже отсеивается,
значит после него всегда `last_slash < rest.size() - 1`, то есть за последним
слэшем есть минимум один символ. Проверка

```cpp
if (project_id.empty()) { return std::nullopt; }
```

не могла сработать ни разу — её ветвь `return` вечно висела непокрытой. Убрана,
рядом оставлен комментарий с инвариантом.

### `path_prefix == "/"`

Разбор path prefix строит `path_prefix` из части после хоста, после чего
срезает все хвостовые слэши:

```cpp
while (!path_prefix.empty() && path_prefix.back() == '/') {
  path_prefix.pop_back();
}
if (path_prefix == "/") {   // ← недостижимо
  path_prefix.clear();
}
```

Цикл уже превращает одиночный `/` в пустую строку, поэтому проверка `== "/"`
после него не могла сработать ни разу. Убрана; комментарий поясняет, что
срезание хвостовых слэшей само нормализует `/`.

## 2. `duplicate_detector::record` — мёртвый guard `m_count < 2`

```cpp
if (entry.m_count < 2) { return {false, 0}; }
```

Ветвь недостижима: элемент попадает в `m_entries` только через создание с
`entry.m_count = 1` (там же и `return {false, 0}` для первого появления), а
перед этой проверкой `m_count` уже инкрементирован (`+= 1`), то есть у
существующего элемента он всегда `>= 2`. Убран; семантика сохранена —
не-дубликат по-прежнему возвращается на ветви «новый ключ».

## 3. `http_client::setup_client` — мёртвая проверка пустого хоста

```cpp
if (parsed_url.m_host.empty()) {
  throw std::runtime_error("Invalid URL: host is empty");
}
```

`setup_client` вызывается ровно из одного места — `prepare_request`
(`http_client.cpp:88-94`), где `ParsedUrl` получен из `parse_url()`. А
`parse_url()` сам бросает `std::runtime_error` при пустом хосте
(`url_utils.hpp:75`). Значит пустой хост сюда не доходит, и ветвь
недостижима. Проверка убрана, комментарий фиксирует: из `ParsedUrl` повторно
проверяется только диапазон порта (этот путь реально тестируется — round 86).

## 4. Что осознанно оставлено

* `catch (...)` / `catch (const std::exception &)` в перечисленных функциях —
  защитные, без инъекции исключения недостижимы, но контракт требует их.
* Проверка диапазона порта в `setup_client` — достижима и покрыта тестом
  «invalid URLs are rejected».
