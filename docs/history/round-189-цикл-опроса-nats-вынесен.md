# round 189 — цикл опроса NATS вынесен из `poll_response` (рефакторинг)

## Что было не так

`NatsPollService::poll_response()` (`src/nats_poll_service.cpp` ✓) — около
130 строк одной функции ✓, в которой смешано:

1. подготовка трейса ✓ (span id, parent id ✓) и ранние выходы ✓ («клиента нет» ✓,
   «соединение пропало» ✓);
2. **цикл опроса** ✓ — переподключение ✓, переотправка ✓, метрики попыток ✓,
   пауза перед следующей попыткой ✓ (около 45 строк ✓);
3. разбор ответа ✓ (span, латентность, возврат данных ✓);
4. обработка исключения ✓.

Цикл опроса — самое ценное и самое тонкое место ✓ (именно в нём живут
переподключение ✓ и backoff ✓), а он был утоплен в общей функции ✓.

## Что сделано

- Цикл вынесен в отдельный метод `poll_until_deadline()` ✓ с результатом
  `PollOutcome` ✓ (ответ ✓ + `consume_span_id` из заголовков NATS ✓ — раньше это
  были локальные переменные, которые пришлось бы возвращать через out-параметры ✓).
- `poll_response()` осталась оркестратором: трейс ✓ → ранние выходы ✓ → вызов
  поллера ✓ → разбор ответа ✓ → исключение ✓.

**~130 → 98 строк** ✓, поведение не изменилось ✓: ни одного изменения в логике
цикла ✓ (перенос дословный ✓), а тесты (в том числе живые NATS-тесты ✓ — поллер
проверяется ими ✓) проходят без правок ✓, количество утверждений то же ✓.

Побочный эффект: у поллера теперь **явный контракт** ✓ — что он возвращает ✓
(`PollOutcome` ✓) — вместо того чтобы разбираться по `reply`/`consume_span_id` в
общей функции ✓.
