# round 187 — выброшенные значения меток per-client-id: `l2_proxy_per_client_id_dropped_labels_total` (P2)

## Что было не так

Семейства метрик с динамической меткой (`DynamicLabeledFamily` ✓ — per-client-id ✓ и
per-IP ✓) **ограничены**: у каждого есть лимит числа значений метки (`max_entries` ✓) и
TTL ✓. При переполнении старые значения меток **вытесняются** ✓, и они просто
исчезают из экспозиции ✓.

Последствие: клиент, который перестал ходить (или превысил лимит уникальных
идентификаторов), **молча пропадает** из top-k панелей ✓ — выглядит как «клиент
прекратил работу», хотя на самом деле его счётчик был вытеснен ✓. Метрики
per-client-id при этом продолжают расти в счётчиках ✓ (теряется только видимость ✓).

## Что сделано

- `DynamicLabeledFamily` получил необязательный счётчик выброшенных значений ✓
  (`prometheus::Counter *dropped_labels` ✓ в конструкторе ✓) и увеличивает его в
  `remove_label()` ✓ — это единственная точка, через которую уходят значения по
  **и** TTL, **и** лимиту ✓ (оба пути вызывают её ✓).
- Новая метрика `l2_proxy_per_client_id_dropped_labels_total` (counter ✓) в реестре
  прокси ✓; все три per-client-id семейства (запросы/отказы ✓, задержка ✓,
  дубликаты ✓) считают свои выбросы в общий счётчик ✓.
- Дашборд L2 Прокси: в панель «Топ client-id» добавлена линия «Выброшено меток/с» ✓
  — теперь исчезновение клиента из top-k читается как «его вытеснили», а не «он
  исчез» ✓.
- Каталоги README и `CATALOG` golden-check ✓ — итого **107** метрик в четырёх
  источниках ✓.

## Почему не тронут per-IP лимитер

У per-IP семейства данные берутся из провайдера лимитера ✓ (`Provider` ✓), а не из
накопленных значений ✓, и вытеснения в нём не происходит ✓ — там свой предел
(`max_ips` ✓) живёт в самом лимитере ✓. Поэтому счётчик выбросов подключён только
к per-client-id семействам ✓, где вытеснение действительно происходит ✓.

## Тест

вытесненное значение **посчитано** ✓ (`dropped == 1` ✓) — иначе исчезновение
значения метки снова стало бы невидимым ✓.
