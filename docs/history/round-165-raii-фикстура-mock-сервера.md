# round 165 — RAII-фикстура mock HTTP-сервера в тестах (поток сервера больше не остаётся висящим)

## Что было не так

Часть тестов поднимала mock HTTP-сервер «руками»:

```cpp
httplib::Server server;
server.Post(".*", handler);
const int port = server.bind_to_any_port("127.0.0.1");
std::thread server_thread([&] { server.listen_after_bind(); });
...
server.stop();
server_thread.join();
```

Жизненный цикл привязан к концу тела теста, а не к объекту. Если в тесте падает
`REQUIRE` (а падать он может и по причине, не связанной с сервером), Catch2
прерывает кейс **до** `server.stop(); server_thread.join();` — и тогда:

- объект `httplib::Server` уничтожается, пока его поток ещё обслуживает запросы
  (use-after-free в потоке);
- поток никогда не присоединяется → «висящий» поток на весь процесс.

Второй вариант — тесты, где сервер поднимается и забывается совсем. Плюс к этому
в шести местах дублировался сам код подъёма/остановки.

## Что стало

- Новый лёгкий заголовок `src/test_http_support.hpp` с фикстурой
  `test_support::MockHttpServer`: биндит эфемерный порт, слушает в фоновом
  потоке и **останавливает поток в деструкторе** — то есть жизненный цикл
  привязан к объекту, а не к порядку строк в тесте.
- Переведены все «сырые» места: `test_sentry_client.cpp` (3 теста) и
  `test_trace_logger.cpp` (3 теста, один из них — с двумя серверами). Ручные
  `stop()`/`join()` из тел убраны: теперь это делает деструктор, и падение
  `REQUIRE` больше не оставляет поток висеть.
- `MockHttpServer` умеет и фиксированный порт (`start(fixed_port)`) — на тот случай,
  когда эндпоинт нужно вернуть на тот же адрес.

Заодно убралось ~40 строк дублирования кода подъёма сервера.

## Почему фикстура вынесена в отдельный заголовок

`test_support.hpp` тянет `app_context.hpp`, `request_handler.hpp`,
`stats_logger.hpp` и `trace_logger.hpp` — для файла, которому нужен только
mock-сервер, это лишняя зависимость и лишнее время компиляции. Новый заголовок
зависит только от `httplib` и стандартной библиотеки.

## Что не менялось

Семантика тестов та же: тот же порт, те же маршруты, те же ожидания. Единственное
отличие — сервер теперь гарантированно останавливается при выходе из кейса (в том
числе при падении проверки).

## Проверка

- Сборка: `All tests passed (2860 assertions in 596 test cases)` и
  `945 assertions in 125 test cases` — набор тестов не изменился (миграция на
  фикстуру не меняет ни одного проверочного утверждения).
- `./health-check.sh all` — все проверки пройдены; `message_counter.py --iterations 1
  --concurrent 1` — все GET-запросы успешны.
- `ci-gate.sh runtime`, cppcheck, clang-tidy `--all` — гейты проверяет CI на этом
  же коммите.
