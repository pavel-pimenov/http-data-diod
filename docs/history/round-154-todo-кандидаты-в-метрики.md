# round 154 — TODO-документ с кандидатами в метрики

## Что сделано

Добавлен планировочный документ `docs/TODO-metrika-kandidaty.md`: разбор того,
каких метрик не хватает сервисам для полноценной обсервабилити. Кода и
регистраций в этом раунде нет — это очередь идей, разобранная по подсистемам.

В документе:

1. **Правило четырёх источников** и чек-лист перед реализацией (уникальность
   имени, ограниченные метки, выбор реестра `l2_common` vs режимный, обновление
   `scripts/generate-grafana-dashboards.py`, README-каталога,
   `scripts/metrics-golden-check.py`, синхронизация env-переменных с
   `docker-compose.yml`).
2. **Карта «что уже покрыто»** по подсистемам (proxy HTTP, rate limiting,
   duplicates, DB/NATS-клиент, task queue, HTTP-пул, worker, worker DB, worker L2,
   tracing/sentry) — чтобы кандидаты заведомо не дублировали существующие 117
   семейств README-каталога.
3. **Кандидаты**, сгруппированные по приоритетам (P1/P2/P3), для каждой позиции —
   имя, тип, метки, место регистрации, что закрывает и риски кардинальности:
   - P1: переходы/отклонения circuit breaker, ожидание/исчерпание DB-пула
     PostgreSQL, типизированные ошибки по готовому `error_categorizer.hpp`,
     таймауты/реконнекты/подписки NATS, ретраи и failover к L2,
     `rejections_total{reason}`, потери трейсов и невалидный traceparent,
     `build_info`, ёмкость очередей и histogram ожидания в очереди воркера;
   - P2: латентность по каждому L2-бэкенду, ожидание pooled-клиента, ошибки
     валидации по полю, ошибки SQL по классу SQLSTATE, histogram числа попыток,
     длительность рендера `/metrics` и `/stats`, здоровье истории метрик,
     причины not-ready, crash dumps, вытеснение дедуп-кэша, срабатывание cap
     динамических семейств, загрузка executor'ов;
   - P3/под вопросом: `startup_seconds`, ошибки конфига, per-connection
     метрики клиента, размер батча экспорта трейсов.
4. **Отклонено осознанно**: любые per-mode метрики/панели/свой `/stats` для
   `l2-server` (тестовый стаб), обсервабилити Oracle-исполнителя (DB-слой только
   PostgreSQL), метки неограниченной кардинальности (`request_id`, сырой
   путь/URL, тело, `client_id` в новых семействах).

Замечание по гейтам: документ лежит в `docs/`, а `scripts/metrics-consistency-check.py`
сканирует только `src/*.cpp|hpp`, README-каталог, dashboards и Perses — имена-кандидаты
из TODO в сверку не попадают и гейт не ломают. При реализации каждой позиции имя
нужно будет добавить во все четыре источника сразу.
