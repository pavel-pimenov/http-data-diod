## ⚠️ ВАЖНО: Проверка сборки перед коммитом

**Правило:** Никогда не коммить изменения в git, пока код не собрался в контейнере!

```bash
# 1. Сначала запусти сборку и тесты
./rebuild-and-run.sh

# 2. Дождись успешной сборки и тестов
# ✅ Все сервисы запущены (healthy)
# ✅ message_counter.py тест прошёл

# 3. Только после успешной сборки делай коммит
git add -A
git commit -m "your message"
```

**Если сборка не проходит:**
- Исправь ошибки компиляции
- Перезапусти ./rebuild-and-run.sh
- Повторяй пока сборка не станет успешной
- ТОЛЬКО ПОСЛЕ ЭТОГО делай коммит

**Исключения:**
- Можно использовать SKIP_PRECOMMIT=1 для черновых коммитов в процессе разработки
- Но перед push в origin/main сборка должна быть успешной

## Git Commit с тестами

Перед коммитом изменения автоматически тестируются через pre-commit hook:

```bash
# Обычный коммит (тесты запустятся автоматически)
git commit -m "your message"

# Если тесты не прошли - коммит будет заблокирован
# Исправь ошибки и попробуй снова

# Пропустить тесты (для черновых коммитов в процессе разработки)
SKIP_PRECOMMIT=1 git commit -m "WIP: work in progress"
```

### Pre-commit скрипт

Для ручного запуска тестов перед коммитом:

```bash
# Запустить тесты и закоммитить если прошли
./scripts/pre-commit.sh "your commit message"

# Только запустить тесты без коммита
./scripts/pre-commit.sh
```

### Health check

Для проверки здоровья всех сервисов:

```bash
./health-check.sh all
```
